# 阶段 12 · 价格采集器对接字典

> 周期：第 22-23 天
> 目标：改造 `run_cpu_crawl_pw.py`，让它从 `data/skus/{week}/_merged/` 读 SKU 全名作为搜索词，按 `{category}/{brand}/{sku}.json` 组织价格输出；原始 CLI 用法（直接传关键词）保持不变。

---

## 任务清单

### CLI 变更
- [ ] 12.1 新增参数（不破坏既有）：
  - `--from-dict YYYY-WW`：从字典读搜索词（与 `--keywords/--keywords-file` 互斥）
  - `--category gpu`（可多选，如 `--category gpu,cpu`）
  - `--brand asus,galax`（可多选，未指定 = 全部）
  - `--chip "RTX 4090,RTX 3090"`（可多选，未指定 = 该品类下全芯片）
  - `--dry-run`：打印将要搜的关键词列表（前 50 条 + 总数），不真跑
  - `--resume`：跳过已存在的 `{sku}.json`（断点续爬）
  - `--failed-retry FAILED.csv`：只重跑失败清单
- [ ] 12.2 保留原始 CLI：`python run_cpu_crawl_pw.py "i5-12400F"` 与 `--keywords`/`--keywords-file` 原样工作

### 搜索词加载
- [ ] 12.3 新增函数 `load_search_terms_from_dict(week, categories, brands, chips) -> list[SkuRef]`：
  - `SkuRef = (category, brand, chip, sku_title, alt_titles)`
  - 过滤不匹配的行；若 `alt_titles` 非空，每个 alt 都独立搜一次（提高召回）
- [ ] 12.4 风险评估：全量跑可能上万 SKU × 3 平台 × 3 页 → 十几小时
  - `--dry-run` 强制用户确认
  - 默认按 `--category` 限制

### 输出变更
- [ ] 12.5 新路径 `data/prices/{week}/{category}/{brand}/{sku_slug}.json`
  - `sku_slug = slug(sku_title)`（小写、非字母数字转 `-`，长度截 80 字符）
  - 文件格式（JSON）：
    ```json
    {
      "week": "2026-W17",
      "category": "gpu",
      "brand": "asus",
      "chip": "RTX 4090",
      "sku_title": "ROG-STRIX-RTX4090-O24G-GAMING",
      "search_terms_used": ["ROG-STRIX-RTX4090-O24G-GAMING"],
      "crawled_at": "2026-04-21T10:00:00+08:00",
      "platforms": {
        "jd":     {"status": "ok", "items": [...]},
        "xianyu": {"status": "no_result", "items": []},
        "taobao": {"status": "anti_spider", "items": []}
      }
    }
    ```
- [ ] 12.6 每个 platform 的 `status` 枚举：`ok | no_result | network_error | login_required | anti_spider | rate_limit | parse_error`
- [ ] 12.7 原始 CLI 的输出路径保持旧结构（`logs/` 下 CSV），兼容现有 `viewer.html`

### 错误处理
- [ ] 12.8 每平台独立重试预算（3 次指数退避），与其他平台解耦
- [ ] 12.9 `AntiSpiderError` / `RateLimitError`：记录当前 SKU 到 `logs/failed_{week}.csv`，继续下一 SKU（不整批中止）
- [ ] 12.10 `LoginRequiredError`：立即中止该平台后续所有 SKU（cookie 失效，继续只会雪崩），其他平台照常
- [ ] 12.11 `ParseError`：记录并继续（选择器失效是局部问题）

### 进度与断点
- [ ] 12.12 tqdm 进度条：双层（category/brand 外层、sku 内层）
- [ ] 12.13 `--resume` 扫描 `data/prices/{week}/` 已存在 json → 跳过
- [ ] 12.14 每完成一个 SKU 立即落盘（不是全部完成再 dump，避免崩了全丢）

## 约束（项目红线）

- **不得** `from core import ...`（`run_cpu_crawl_pw.py` 必须保持自包含，与 `core/` 解耦——CLAUDE.md 写明）
- 节流常量（`SCROLL_DELAY_MS` / `PAGE_DELAY_MS` / `PLATFORM_DELAY_SEC` / `JD_PAGE_DELAY_MS` / `CAPTCHA_WAIT_SEC`）继续使用，**不调低**
- 异常分类严格按 `CLAUDE.md` 的表（`NetworkError` 可重试，`AntiSpiderError/LoginRequiredError` 不可自动重试等）
- 所有 JSON dump `ensure_ascii=False, indent=2`，文件写 `encoding='utf-8'`

## 已知坑

- 冷门 SKU（古董 / 停产）三平台可能全 `no_result`：**不算失败**，status 写 `no_result` 并保留文件，避免下次 `--resume` 重跑
- 淘宝滑块：仅 `--headed` 能过，批量模式遇到滑块 → `AntiSpiderError` 记入 failed，不卡住
- `sku_slug` 过长截断时可能撞名 → 尾部加 6 位 hash 防撞
- JD 风控在机房 IP 下搜索页空白（CLAUDE.md 红线） → 与原脚本行为一致，不改逻辑
- `alt_titles` 双重搜索会让 JD 请求翻倍 → 同一 SKU 的三平台结果合并到一个 json，去重 items

## 验收标准

- `python run_cpu_crawl_pw.py --from-dict 2026-W17 --category gpu --chip "RTX 4090" --dry-run` 打印将搜的关键词列表
- `python run_cpu_crawl_pw.py --from-dict 2026-W17 --category gpu --brand asus --chip "RTX 4090" --pages 2 --headed` 跑完产出 `data/prices/2026-W17/gpu/asus/rog-strix-rtx4090-*.json`
- 中途 Ctrl+C 后 `--resume` 续跑不重复已完成 SKU
- 原始 CLI `python run_cpu_crawl_pw.py "i5-12400F" --pages 2` 行为无变化，输出仍在 `logs/` 下
- `python -m py_compile run_cpu_crawl_pw.py` 通过
- `/codex:rescue` 审查通过（异常分类无降级 / 节流常量未被调低 / 断点续爬无幂等漏洞 / 自包含未破）
