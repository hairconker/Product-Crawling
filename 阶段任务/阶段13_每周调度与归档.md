## 已知坑

- 每周全量阶段 12 跑耗时不确定（取决于 SKU 数 × 平台 × 翻页），可能 6+ 小时 → 调度器超时设 24h 或分段跑
- WSL 上 Windows 计划任务无法直接调 `wsl python ...`：用 `scripts/weekly_run.bat` wrap；或 systemd timer 在 WSL 内跑
- 跨平台 zip 路径分隔：用 `zipfile.ZipFile` + `pathlib.PurePosixPath` 统一
- viewer 加载整周目录浏览器内存压力大（几 GB 价格数据）→ 懒加载 + 只读元数据索引，详情点击再拉
- 归档保留策略与阶段 9/10/11 的"仅当周"产出冲突：归档时必须同步清旧 `data/skus/` 和 `data/dict/`，否则碎片累积

## 约束

- 调度脚本走标准库 + 已有依赖，**不新增**依赖（除可选 `win10toast`）
- 归档必须**原子**：先打包成 `.zip.tmp` 成功后 rename，再删原目录（避免中途崩溃丢数据）
- viewer 保持纯前端（无后端），与 CLAUDE.md "配套工具"约束一致

## 验收标准

- 手动 `python scripts/weekly_run.py --only dict` 产出当周 `data/dict/` + `data/skus/_merged/`
- 手动 `python scripts/weekly_run.py --only prices --categories gpu --headed` 产出当周 `data/prices/gpu/`
- `python scripts/archive.py --dry-run --keep-weeks 2` 正确列出 12 周前的目录
- `viewer.html` 在浏览器加载某周 `data/prices/YYYY-Www/` 后能按品类+品牌过滤，能看多周趋势
- 旧 `run_cpu_crawl_pw.py` / `run_jd_drission.py` 的 logs CSV 仍能拖入 viewer（向后兼容）
- `/codex:rescue` 审查通过（原子归档 / 跨平台路径 / 调度失败隔离 / viewer 无后端泄漏）
